## Google Workspace Native Tools (Session Summary)

### gog replaced with native tools

- **GoogleWorkspaceTool** (`gerty/tools/google_workspace_tool.py`) — Calendar, Gmail, Drive via `check_google_*.py` scripts using `google-token.json`. No gog required.
- **Routing** — When `GERTY_GOOGLE_NATIVE_ENABLED=True` (default), calendar/email/drive intents route to `PROVIDER_TOOL` instead of OpenClaw.
- **gog** — Optional/legacy. Set `GERTY_GOOGLE_NATIVE_ENABLED=False` to fall back to gog via OpenClaw.

### Personalization (count + unread)

- **Count parsing** — "last 3 unopened emails", "show 5 files" → extracts count (1–50) and passes to scripts.
- **Unread filter** — "unopened", "unread", "need to respond to" → Gmail script uses `is:unread`.
- **Client emails** — Not implemented. "Any client emails?" returns all unread; would need Gmail label or configurable sender list.

### Vision gap (important)

**Vision:** Gerty as Jarvis-style assistant—fetch, read, create draft, respond, move, edit, delete as requested.

**Reality:** Read-only. Three scripts: list calendar, list emails, list drive. No create/draft/reply/send/move/delete. OAuth requests broader scopes but scripts use read-only only. Documented in `docs/GOOGLE_WORKSPACE_STATUS.md`.

## Desktop Runtime Integrity (Stabilization)

### Problem

"check my calendar for next week" in desktop app returned native OAuth hints (`google_oauth_flow.py`, `check_google_workspace.sh`) instead of OpenClaw/gog data. The empty-output message was wrong for the OpenClaw path.

### Fix

- **OpenClaw-specific empty message** — `_empty_output_message(from_openclaw=True)` now gives gog/exec/daemon hints, not native OAuth.
- **Runtime integrity report** — `GET /api/runtime-integrity`: config_hash, daemon_reachable, gog_available, openclaw_env_exists, google_routing.
- **Trace endpoint** — `POST /api/trace-route` with message returns intent, provider, execution_path.
- **Settings → Runtime** — Visible status: config hash, Google routing, daemon, gog, ~/.openclaw/.env.
